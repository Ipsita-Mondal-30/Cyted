# Data Models

All models live in PostgreSQL (Supabase-hosted) and are defined in `prisma/schema.prisma`. Prisma is the ORM used throughout the codebase.

---

## Entity Relationship Overview

```
User (1) ──────────── (0..1) Company
  │                              │
  │ (1)                          │ (1)
  │                              │
  └────────── (many) AnalysisJob ┘
                      │
          ┌───────────┼───────────┬──────────────┬──────────────┐
          │           │           │              │              │
       (many)      (many)      (0..1)         (0..1)        (0..1)
          │           │           │              │              │
       Prompt      Response    Metrics    Recommendation  SystemConfig*
          │           │
       (1) └──(many)──┘ (many)
                │
            (0..1)
                │
         ExtractedResult

* SystemConfig is a singleton, not related to AnalysisJob
```

## Models

### User

Mirrors the Supabase Auth user. Created/upserted on every authenticated API call via `requireUser()`.

```prisma
model User {
  id        String   @id @db.Uuid      // matches Supabase Auth user ID exactly
  email     String
  name      String?
  avatarUrl String?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  company   Company?        // one-to-one
  analyses  AnalysisJob[]   // one-to-many
}
```

Key notes:
- `id` is a UUID that matches the Supabase Auth `user.id` — never auto-generated by Prisma
- `name` and `avatarUrl` are synced from Google OAuth `user_metadata` on each login
- One user can have at most one `Company` and many `AnalysisJob`s

---

### Company

Represents the user's company profile. There is exactly one Company per User (unique constraint on `userId`). It is upserted on every analysis creation so it always reflects the most recent run.

```prisma
model Company {
  id          String   @id @default(cuid())
  userId      String   @unique @db.Uuid   // enforces one company per user
  name        String
  website     String?
  description String?
  competitors Json     @default("[]")     // string[] stored as JSON
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  user      User          @relation(fields: [userId], references: [id], onDelete: Cascade)
  analyses  AnalysisJob[]
}
```

Key notes:
- `competitors` is a JSON array of strings (brand names), not normalized rows
- The worker also updates this record after brand name correction (Step 0)
- Cascade deletes: deleting a User removes the Company and all its analyses

### AnalysisJob

The central entity. Represents one full analysis run — from QUEUED through to COMPLETED or FAILED.

```prisma
model AnalysisJob {
  id              String         @id @default(cuid())
  userId          String         @db.Uuid
  companyId       String

  // Snapshot of inputs at creation time (may differ from Company after correction)
  companyName     String
  website         String?
  description     String?
  competitors     Json           @default("[]")   // string[] — updated after brand resolution

  // Job lifecycle
  status          AnalysisStatus @default(QUEUED)
  progress        Int            @default(0)       // 0–100
  progressMessage String?                          // human-readable step label
  error           String?                          // set on FAILED
  warnings        Json           @default("[]")    // soft-fail messages (string[])

  // Enriched data (written by worker)
  companyContext  Json?           // { industry, products, services, audience, useCases, keywords, brandLogos, brandDomains }

  createdAt       DateTime       @default(now())
  completedAt     DateTime?

  user            User             @relation(...)
  company         Company          @relation(...)
  prompts         Prompt[]
  responses       Response[]
  metrics         Metrics?
  recommendation  Recommendation?

  @@index([userId])
  @@index([status])
}

enum AnalysisStatus {
  QUEUED
  PROCESSING
  COMPLETED
  FAILED
}
```

Key notes:
- `companyName` and `competitors` start as user input but are overwritten by the worker after AI-powered brand resolution
- `companyContext` is a large JSON blob containing the company profile (industry, products, keywords) plus resolved `brandLogos` (Clearbit CDN URLs) and `brandDomains`
- `progress` is polled by the UI every 2 seconds; it increments at each pipeline step
- `warnings` is a soft-fail log — the job can complete with warnings (e.g. recommendations failed)
- Indexes on `userId` (dashboard list queries) and `status` (worker queue lookups)

#### Status Lifecycle

```
API creates job ──► QUEUED
                       │
Worker picks up ──────►│
                       ▼
                   PROCESSING  (progress: 5 → 100)
                       │
           ┌───────────┴───────────┐
           ▼                       ▼
       COMPLETED               FAILED
   (progress: 100)         (error set, BullMQ retries)
```

### Prompt

One generated buyer-intent search query. Each analysis has `N categories × M prompts_per_category` prompts (default: 6 categories × 2 = 12 prompts).

```prisma
model Prompt {
  id         String   @id @default(cuid())
  analysisId String
  category   String   // e.g. "Comparison", "Buying", "Pricing", "Reviews", "Features", "Alternatives"
  prompt     String   // the actual query text sent to AI providers

  createdAt  DateTime @default(now())

  analysis  AnalysisJob @relation(...)
  responses Response[]

  @@index([analysisId])
}
```

Key notes:
- Categories are configurable via `PROMPT_CATEGORIES` env var
- Prompts are a mix of branded ("compare Acme vs competitors") and unbranded ("best CRM for small teams") queries
- All prompts are deleted at the start of a retry to avoid duplicates

---

### Response

One raw AI response from one provider for one prompt. Every `(prompt × provider)` combination produces a Response row, including failures.

```prisma
model Response {
  id          String   @id @default(cuid())
  analysisId  String
  promptId    String
  provider    String   // "openai" | "gemini" | "claude" | "groq"
  model       String   // exact model string used
  rawResponse String?  // full text returned by the provider (null on error)
  latencyMs   Int?     // wall-clock time for the API call
  error       String?  // error message if the call failed (null on success)

  createdAt   DateTime @default(now())

  analysis  AnalysisJob      @relation(...)
  prompt    Prompt           @relation(...)
  extracted ExtractedResult? // null until extraction step runs, or if error is set

  @@index([analysisId])
  @@index([promptId])
}
```

Key notes:
- Error rows (where `error` is not null) are stored so the admin usage dashboard can report failure rates
- `rawResponse` can be large — full web-search-augmented LLM responses, potentially several KB each
- Extraction only runs on rows where `error` is null

### ExtractedResult

Structured data extracted from one Response by a second LLM pass. Contains the actual brand mention signal.

```prisma
model ExtractedResult {
  id                String   @id @default(cuid())
  responseId        String   @unique          // one-to-one with Response

  mentionedBrands   Json     @default("[]")   // string[] — all brands named in the response
  mentionedProducts Json     @default("[]")   // string[] — specific products named
  citations         Json     @default("[]")   // string[] — URLs cited by the AI

  ranking           Int?     // 1-based position of the target company in any ranked list (null if not ranked)
  reasoning         String?  // LLM explanation for its extraction
  sentiment         String?  // "Positive" | "Neutral" | "Negative" — toward the target company

  createdAt         DateTime @default(now())

  response Response @relation(...)
}
```

Key notes:
- `mentionedBrands` is used for share-of-voice and competitor comparison calculations
- `ranking` drives the average ranking metric and the ranking hero section in the UI
- `sentiment` is the basis for the positive sentiment rate metric
- `citations` feeds the citation rate metric

### Metrics

Aggregated numeric scores computed from all ExtractedResults for an analysis. One row per job.

```prisma
model Metrics {
  id                  String   @id @default(cuid())
  analysisId          String   @unique

  visibilityScore     Float    // weighted composite score (0–100)
  mentionRate         Float    // % of prompts where company was mentioned
  shareOfVoice        Float    // company mentions / total brand mentions (0–100)
  citationRate        Float    // % of company mentions that included citations
  recommendationRate  Float    // % of responses where company was positively recommended
  avgRanking          Float?   // mean ranking position (null if never ranked)

  competitorShare     Json     @default("{}")
  // Map of brand → fraction (0–1), e.g. { "Acme": 0.4, "Rival": 0.3 }
  // ALSO contains a hidden "__positiveSentimentRate" key (see note below)

  createdAt           DateTime @default(now())

  analysis AnalysisJob @relation(...)
}
```

#### Metric Calculations

| Metric | Formula |
|---|---|
| `mentionRate` | unique prompt IDs with company mention / total prompt IDs × 100 |
| `shareOfVoice` | company total mentions / (company + all competitor mentions) × 100 |
| `citationRate` | extractions with citations where company mentioned / company mention count × 100 |
| `recommendationRate` | responses where company mentioned AND (positive sentiment OR ranking ≤ 3) / total responses × 100 |
| `avgRanking` | mean of all non-null ranking values |
| `visibilityScore` | `mentionRate×0.35 + shareOfVoice×0.25 + recommendationRate×0.25 + citationRate×0.10 + rankingScore×0.05` |

> **Implementation note**: `positiveSentimentRate` is stored as `competitorShare.__positiveSentimentRate` to avoid a schema migration. It is extracted by `serializeAnalysisReport()` and exposed as a first-class field in the API response.

### Recommendation

Stores the AI-generated strategic report for the analysis. One row per job.

```prisma
model Recommendation {
  id         String   @id @default(cuid())
  analysisId String   @unique
  content    String   // JSON-encoded { markdown: string, contentSuggestions: ContentSuggestion[] }
  createdAt  DateTime @default(now())

  analysis AnalysisJob @relation(...)
}
```

Key notes:
- `content` is stored as a JSON string but contains a structured object. Parsed by `parseRecommendationContent()` in `recommendation.service.ts`
- `markdown` is a full strategic report rendered in the UI via `react-markdown`
- `contentSuggestions` is an array of specific content ideas: `{ type, title, rationale, keywords[], estimatedImpact }`
- This step is **soft-fail** — if the LLM call fails, the job completes with a warning instead of failing

### SystemConfig

Singleton configuration row for admin-controlled feature flags.

```prisma
model SystemConfig {
  id                String   @id @default("default")   // always "default"
  enabledProviders  Json     @default("{}")
  // { openai?: boolean, gemini?: boolean, claude?: boolean, groq?: boolean }
  updatedAt         DateTime @updatedAt
}
```

Key notes:
- Only one row ever exists (`id = "default"`)
- Written by `PUT /api/admin/providers`, read by `getProviderFlags()` in `provider-settings.service.ts`
- A provider is **active** only when its API key is set in env AND its flag here is `true` (or absent/undefined, which defaults to true)
- Read fresh on every job — no caching — so admin toggles take effect for the next job immediately

## JSON Field Schemas

Several fields store structured JSON. Here are the shapes:

### `AnalysisJob.competitors`
```json
["Competitor A", "Competitor B", "Competitor C"]
```

### `AnalysisJob.companyContext`
```json
{
  "industry": "CRM Software",
  "products": ["Sales CRM", "Marketing Hub"],
  "services": ["Onboarding", "Support"],
  "audience": ["SMBs", "Sales teams"],
  "useCases": ["Lead tracking", "Pipeline management"],
  "keywords": ["crm", "sales software", "pipeline"],
  "brandLogos": {
    "Acme": "https://logo.clearbit.com/acme.com",
    "Rival": "https://logo.clearbit.com/rival.com"
  },
  "brandDomains": {
    "Acme": "acme.com",
    "Rival": "rival.com"
  }
}
```

### `Metrics.competitorShare`
```json
{
  "Acme": 0.42,
  "Rival": 0.31,
  "Other": 0.15,
  "__positiveSentimentRate": 0.68
}
```

### `Recommendation.content`
```json
{
  "markdown": "## Strategic Report\n\nYour brand appeared in...",

      "keywords": ["acme vs rival", "crm comparison"],
      "estimatedImpact": "High"
    }
  ]
}
```
